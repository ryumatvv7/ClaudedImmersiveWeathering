# Immersive Weathering — порт на Fabric 26.1.2 (заметки)

Неофициальный приватный порт. Оригинал: https://github.com/Silversmith-Mods/Immersive-Weathering
Авторы оригинала: Ordana, MehVahdjukaar, Keyberries, kayla_the_bee. Лицензия LGPL-3.0 (`LICENSE`),
благодарности — `ATTRIBUTIONS`.

## Какая версия взята за основу
Ветка `1.21.1`, коммит `1bcc03b6` («versions», 2025-01-23) — это полная версия **1.20.1-2.0.5**.
Последний коммит ветки (`07dca6c9`, «nixxing split features», 2026-05-08) вырезает из кода ржавчину,
кучи листьев, кору, почвы, мульчу, сорняки, плющ и цветочный венок (‑5273 строки) и сам не
компилируется, поэтому он **не используется**. Оригинальные исходники лежат в `upstream/`
(в git порта не входят, только для справки, checkout на `1bcc03b6`).

## Структура
- `src/main` — общий код (клиент + выделенный сервер). Клиентские классы здесь недоступны
  на уровне компиляции (`splitEnvironmentSourceSets`).
- `src/client` — только клиент (рендер, частицы, обработчики пакетов).
- `pending/` — исходники оригинала, ещё не перенесённые в сборку (этапы 3–4).
- `tools/` — одноразовые скрипты порта (конвертер ресурсов, миграция сигнатур) и
  `test-server.sh` / `test-client.sh` для проверки запуска.
- Готовый jar: `build/libs/immersive_weathering-<версия>.jar` (не `-sources`).

## Этапы
- [x] Этап 1 — каркас: проект собирается, выделенный сервер стартует с Moonlight.
- [x] Этап 2 — блоки, предметы, сущности, конфиг, ресурсы и данные под новые форматы.
- [x] Этап 3 — механики: data-driven `block_growths` / `fluid_generators`, миксины, события
      (клики инструментами, огонь, молния), инъекции лута, пакет распада листьев.
- [x] Этап 4 — генерация мира, частицы, клиентский рендер, сеть, динамические ресурсы.

Инструкция по серверу: `SERVER_SETUP.md`.

## Что сделано на этапе 2
- Все блоки (включая ржавое железо, почвы, мульчу, сорняки, плющ, иней, сосульки, тонкий лёд,
  кучи листьев) и предметы зарегистрированы; классы блоков перенесены вместе со своей логикой
  случайных тиков (мох, трещины, ржавчина, снег/песок на блоках и т.д.).
- Кучи листьев и кора регистрируются динамически для всех типов дерева через Moonlight `BlockSetAPI`.
- Серверный конфиг — Moonlight `ConfigType.COMMON_SYNCED`: значения приходят с сервера всем игрокам.
- Ресурсы сконвертированы скриптом `tools/ConvertResources.java`: рецепты (349), лут-таблицы,
  достижения, теги (новые имена папок), описания предметов `assets/.../items/*.json`,
  equipment-ассеты венка.

## Что сделано на этапе 3
- `block_growths` (78 файлов) и `fluid_generators` (14) грузятся с датапаками на сервере; кодеки
  переведены на `MapCodec`-диспетчеризацию, свой загрузчик `RegistryJsonReloadListener`.
- Серверный цикл случайных тиков (`ServerLevelMixin`) запускает рост блоков; всё работает только
  на сервере.
- Действия инструментами (кирка, кирпич, ножницы, топор, стальная вата, губка, песок, снежок) —
  через Fabric `UseBlockCallback`; огонь и молния — через события Moonlight.
- Инъекции лута (сало, пепел, сундуки, подарки жителей) — через Moonlight `addLootTableInjects`.
- Эффект распада листьев — Fabric payload `LeafDecayPayload` (сервер → клиенты рядом).
- Проверка в dev: `tools/test-server.sh` запускает сервер с аудитом всех миксинов и самотестом
  `DevSelfTest` (тики всех ~41 тыс. состояний блоков мода, рост, жидкости, молния, инструменты).
  В обычной игре самотест и аудит выключены (нужны системные свойства `iw.selfTest`, `iw.mixinAudit`).

## Что сделано на этапе 4
- Генерация мира: фича сосулек, патчи почв, иней, плющ, мох, дюнная трава; JSON фич переведён на
  форматы 26.1 (`tools/FixWorldgen.java`), подключение к биомам через Fabric Biome API.
  Замены ванильных деревьев (корни под большими деревьями) пересобраны из ванильных файлов 26.1.
- Частицы переписаны под новый API (`ModParticleProviders`): искры, лепестки/листья, мох, счистка ржавчины.
- Окраска блоков через `BlockTintSource` (трава на почвах, иней на траве, кучи листьев буреют с возрастом),
  окраска предметов — в `assets/.../items/*.json`.
- Динамические ресурсы для деревьев из других модов (клиент: модели и описания предметов; сервер: теги,
  лут, рецепт) на новом API динамических паков Moonlight.
- Встроенный опциональный ресурспак `visual_waxed_iron_items`.
- Автотесты (только dev): `gradlew runClientGameTest` — клиент сам заходит в одиночный мир, ставит все
  блоки мода, делает скриншоты (`build/run/clientGameTest/screenshots`), затем поднимает выделенный
  сервер и подключается к нему. Готовый jar дополнительно проверен на настоящем Fabric-сервере.

## Изменено относительно оригинала
- **Динамические ресурсы упрощены**: «тяжёлая» куча листьев модовых деревьев использует обычную текстуру
  листвы, иконка модовой коры — текстуру бревна (в оригинале текстуры перекрашивались по палитре).
  На ванильные породы не влияет.
- Песчаные ступени/плиты/стены: состояние по умолчанию больше не «с водой» (ошибка оригинала).
- **Подмена ванильных блоков** (кирпичи, камень, железные решётки/двери и т.д. — 56 штук):
  в оригинале 56 `@Redirect` на конструкторы внутри `Blocks.<clinit>`; в 26.1 блоки создаются
  фабриками, поэтому теперь один миксин на `Blocks.register` и таблица `VanillaBlockReplacements`.
- **Миксины, заменённые ванильными тегами** (в 26.1 для этого появились теги): посадка и рост
  культур и стеблей на плодородных блоках (`supports_crops`, `grows_crops`, `supports_*_stem`),
  адский нарост и грибы на нульче (`supports_nether_wart`, `supports_*_fungus`, `supports_*_roots`,
  `supports_nether_sprouts`), пузырьковые колонны (`enables_bubble_column_*`), приманка кроликов
  сорняками (`rabbit_food`). Миксинов стало 21 вместо 32.
- Правило `doFireTick` стало радиусом (`fire_spread_radius_around_player`): сажа от огня появляется,
  когда он не равен 0.
- Сорняки теперь горят (в оригинале горючесть была объявлена только Forge-методами).
- Убраны Architectury и Forge, один обычный Fabric-проект.
- Интеграции EMI, Quark, Serene Seasons, Trinkets/Curios, Create, Snow Real Magic не перенесены
  (EMI/ModMenu можно вернуть в конце).
- **Еда** (сосулька, комок мха, цветы азалии): через компоненты `food` + `consumable`.
  Опция `icicle_food` теперь проверяется при использовании; огнестойкость от сосульки выдаётся
  кодом и подчиняется опции `icicle_fire_resistance` (в оригинале опция не работала).
- **Ледяной серп**: `SwordItem` больше нет — характеристики через `Item.Properties.sword`,
  ремонт по тегу `immersive_weathering:icicle_tool_materials`.
- **Цветочный венок**: `ArmorItem` больше нет. Текстура именных венков выбирается на сервере
  (компонент `equippable` обновляется по имени предмета и синхронизируется ванилью), а не
  клиентским миксином; иконка — через `select` по компоненту `custom_name` (имя должно быть
  написано как `bee`, `Bee` или `BEE`). Частицы венка шлёт сервер — их видят все игроки.
- **Фульгурит и трезубец с «Громовержцем»**: зачарование стало data-driven, поэтому фульгурит
  добавлен в тег `minecraft:lightning_rods`, код в блоке убран.
- **Сосульки и вибрации**: в оригинале громкость события искалась по неверному ключу и падение
  от вибраций фактически не срабатывало; исправлено (опция `react_to_vibrations`).
- **Снежные/песчаные блоки и вода**: новый API обновления соседей не сообщает позицию соседа,
  поэтому проверяются все шесть сторон.
- Слои рендера блоков (cutout/translucent) больше не регистрируются кодом — 26.1 определяет их
  по прозрачности текстур.
- Время горения (обугленные блоки, кора) — через Fabric `FuelValueEvents`.
- Рецепт `loam`: список «тег + предмет» больше не допускается, добавлен тег
  `immersive_weathering:loam_sand`.
- Переопределения ванильных достижений `husbandry/wax_on|wax_off` не перенесены.

## Известные баги / что ещё не работает
- **Бледный дуб** (`pale_oak`, появился после 1.20.1): статические ресурсы добавлены скриптом
  `tools/AddPaleOak.java` (модели на ванильной текстуре листвы, рецепты, лут, теги; текстура коры —
  перекрашенная кора дуба). Если в игре появятся новые ванильные породы, нужно повторить.
- Экран настроек через ModMenu и интеграция EMI не перенесены (конфиг правится в файле или через
  экран конфигов Moonlight, если он доступен).
- Обугливание дерева огнём идёт через событие Moonlight и автотестом не покрыто (огонь не тикает без
  игрока рядом) — проверить в игре.
- В логе есть `Registry 'moonlight:world_saved_data_type' was empty after loading` —
  это сообщение самой Moonlight, не ошибка порта.

## Дополнения после тестов (пепел, настройки)
- [x] Пепел (своё решение, в 2.0.5 его не было): блок `ash_layer_block` (слой 1–8, падает, смывается дождём) и предмет `ash`
  (ставит слой, на растениях работает как костная мука). Появляется, когда огонь уничтожает блок (если блок не обуглился)
  и когда огонь гаснет. Блейзы теперь роняют пепел вместо сажи. Под пеплом трава становится землёй (настраивается).
- [x] Конфиг: секция `speed` (global + категории vegetation, frost_and_ice, fire_and_soot, sand, coral, lightning,
  leaf_piles, nether, weeds, other, moss, cracks, rust) и секция `ash`. Множитель применяется ко всем block growth,
  включая датапаки (`ScaledBlockGrowth`).

# Immersive Weathering — порт на Fabric 26.1.2 (заметки)

Неофициальный приватный порт. Оригинал: https://github.com/Silversmith-Mods/Immersive-Weathering
Авторы оригинала: Ordana, MehVahdjukaar, Keyberries, kayla_the_bee. Лицензия LGPL-3.0 (`LICENSE`),
благодарности — `ATTRIBUTIONS`.

## Какая версия взята за основу
Ветка `1.21.1`, коммит `1bcc03b6` («versions», 2025-01-23) — это полная версия **1.20.1-2.0.5**.
Последний коммит ветки (`07dca6c9`, «nixxing split features», 2026-05-08) вырезает из кода ржавчину,
кучи листьев, кору, почвы, мульчу, сорняки, плющ и цветочный венок (‑5273 строки) и сам не
компилируется, поэтому он **не используется**. Оригинальные исходники лежат в `upstream/`
(в git порта не входят, только для справки, checkout на `1bcc03b6`).

## Структура
- `src/main` — общий код (клиент + выделенный сервер). Клиентские классы здесь недоступны
  на уровне компиляции (`splitEnvironmentSourceSets`).
- `src/client` — только клиент (рендер, частицы, обработчики пакетов).
- `pending/` — исходники оригинала, ещё не перенесённые в сборку (этапы 3–4).
- `tools/` — одноразовые скрипты порта (конвертер ресурсов, миграция сигнатур) и
  `test-server.sh` / `test-client.sh` для проверки запуска.
- Готовый jar: `build/libs/immersive_weathering-<версия>.jar` (не `-sources`).

## Этапы
- [x] Этап 1 — каркас: проект собирается, выделенный сервер стартует с Moonlight.
- [x] Этап 2 — блоки, предметы, сущности, конфиг, ресурсы и данные под новые форматы.
- [ ] Этап 3 — механики: data-driven `block_growths` / `fluid_generators`, миксины, события
      (клики инструментами, огонь, молния), инъекции лута.
- [ ] Этап 4 — генерация мира, частицы, клиентский рендер, сеть, динамические ресурсы.

## Что сделано на этапе 2
- Все блоки (включая ржавое железо, почвы, мульчу, сорняки, плющ, иней, сосульки, тонкий лёд,
  кучи листьев) и предметы зарегистрированы; классы блоков перенесены вместе со своей логикой
  случайных тиков (мох, трещины, ржавчина, снег/песок на блоках и т.д.).
- Кучи листьев и кора регистрируются динамически для всех типов дерева через Moonlight `BlockSetAPI`.
- Серверный конфиг — Moonlight `ConfigType.COMMON_SYNCED`: значения приходят с сервера всем игрокам.
- Ресурсы сконвертированы скриптом `tools/ConvertResources.java`: рецепты (349), лут-таблицы,
  достижения, теги (новые имена папок), описания предметов `assets/.../items/*.json`,
  equipment-ассеты венка.

## Изменено относительно оригинала
- Убраны Architectury и Forge, один обычный Fabric-проект.
- Интеграции EMI, Quark, Serene Seasons, Trinkets/Curios, Create, Snow Real Magic не перенесены
  (EMI/ModMenu можно вернуть в конце).
- **Еда** (сосулька, комок мха, цветы азалии): через компоненты `food` + `consumable`.
  Опция `icicle_food` теперь проверяется при использовании; огнестойкость от сосульки выдаётся
  кодом и подчиняется опции `icicle_fire_resistance` (в оригинале опция не работала).
- **Ледяной серп**: `SwordItem` больше нет — характеристики через `Item.Properties.sword`,
  ремонт по тегу `immersive_weathering:icicle_tool_materials`.
- **Цветочный венок**: `ArmorItem` больше нет. Текстура именных венков выбирается на сервере
  (компонент `equippable` обновляется по имени предмета и синхронизируется ванилью), а не
  клиентским миксином; иконка — через `select` по компоненту `custom_name` (имя должно быть
  написано как `bee`, `Bee` или `BEE`). Частицы венка шлёт сервер — их видят все игроки.
- **Фульгурит и трезубец с «Громовержцем»**: зачарование стало data-driven, поэтому фульгурит
  добавлен в тег `minecraft:lightning_rods`, код в блоке убран.
- **Сосульки и вибрации**: в оригинале громкость события искалась по неверному ключу и падение
  от вибраций фактически не срабатывало; исправлено (опция `react_to_vibrations`).
- **Снежные/песчаные блоки и вода**: новый API обновления соседей не сообщает позицию соседа,
  поэтому проверяются все шесть сторон.
- Слои рендера блоков (cutout/translucent) больше не регистрируются кодом — 26.1 определяет их
  по прозрачности текстур.
- Время горения (обугленные блоки, кора) — через Fabric `FuelValueEvents`.
- Рецепт `loam`: список «тег + предмет» больше не допускается, добавлен тег
  `immersive_weathering:loam_sand`.
- Переопределения ванильных достижений `husbandry/wax_on|wax_off` не перенесены.

## Известные баги / что ещё не работает
- Механики этапа 3 ещё не подключены: нет роста по `block_growths`, генераторов из жидкостей,
  действий инструментами (скол, счистка мха/ржавчины, кора топором), обугливания от огня,
  реакции на молнию, инъекций лута (сало и т.п.), изменений ванильных блоков миксинами.
- Клиент (этап 4): частицы мода пока используют простое ванильное поведение; нет окраски
  инея на траве и куч листьев по биому; нет пакета частиц распада листьев.
- **Бледный дуб** (`pale_oak`, появился после 1.20.1): куча листьев и кора регистрируются, но для
  них нет моделей/текстур/рецепта/лута — будут сгенерированы динамическими ресурсами на этапе 4.
- Куча листьев и сорняки пока не горят (в оригинале на Fabric тоже) — добавить в
  `FlammableBlockRegistry` на этапе 3.
- Генерации мира нет (этап 4).
- В логе есть `Registry 'moonlight:world_saved_data_type' was empty after loading` —
  это сообщение самой Moonlight, не ошибка порта.
